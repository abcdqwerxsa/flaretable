# 01. 产品需求文档 (PRD) — FlareTable（飞格多维表格）

## 1. 背景与痛点

在实际自动化工程（如 n8n 工作流编排、AI Agent 任务执行、多平台内容管理与客户线索收集）中，团队通常面临两难困境：

1. **传统 SaaS 多维表格（如飞书多维表格、Airtable）的局限**：
   - 开放 API 存在严格的 QPS 限流与租户授权链路（获取 `tenant_access_token` 繁琐、Token 两小时过期）。
   - 字段接口强制绑定内部 `fld_xxx` 乱码 Key 或嵌套结构，在 n8n 中拼装写入参数极易出错。
   - 缺少开箱即用的原生 MCP（Model Context Protocol）支持，AI Agent 往往需要额外开发并部署 MCP Bridge。
   - 高级自动化 Webhook、大批量记录同步及附件空间受限于高昂的按席位付费档位。
2. **自建开源表格系统（如 NocoDB / Teable）的运维负担**：
   - 强依赖常驻 VPS、PostgreSQL、Redis 与对象存储桶，冷启动慢、运维成本高且需要持续打补丁与备份数据库。

**FlareTable** 致力于以 **Cloudflare Workers Paid（\$5/月）** 为唯一运行时基座，构建一个**零运维服务器、边缘毫秒响应、对 n8n 与 AI Agents 极度友好**的 Web 多维表格系统。

---

## 2. 产品定位与核心设计原则

- **定位**：以多维强类型表格为交互前端、以 Edge SQLite + 异步事件队列为内核的个人/团队自动化数据中枢。
- **原则 1（数据无锁与双键名访问）**：所有外部 API 既支持稳定不变的 `fld_xxx` 字段 ID，也原生支持可读的中文/英文字段名（`fieldKeyType=name`），且保证在界面重命名字段时历史数据永不丢失。
- **原则 2（幂等优先）**：为 n8n 同步场景内置基于指定唯一键的 `POST /records/upsert` 接口，防止重复抓取或工作流重试导致脏数据。
- **原则 3（原生协同与通知）**：任何来源（浏览器人工编辑、公开表单、n8n、AI Agent MCP）引发的数据变更，都会实时推送至所有在线客户端，并可靠进入异步队列触发下游 Webhook。
- **原则 4（配额自律）**：充分榨干 \$5/月套餐免费包含的计算、D1、DO、KV 与 Queues 额度，同时针对 R2 存储实施严格配额守卫，绝不冲击用户同一账户下已有的服务器快照空间。

## 4. 功能需求矩阵 (MVP v1.0)

### 4.1 空间与表结构引擎
- **多空间（Base）管理**：采用飞书多维表格风格，支持开箱即建纯净空白空间（默认生成空白「数据表 1」及基础列、0 条假数据），并支持空间重命名与删除。
- **多数据表（Table）管理**：每个空间下支持自由创建、重命名、删除数据表，支持跨表 `link` 关联与 `lookup` 查找引用。
- **13 种强类型字段**：
  - 基础型：`text`、`number`、`checkbox`、`date`、`url`、`email`
  - 选项型：`single_select`、`multi_select`（支持标签名称、自定义色板）
  - 结构与文件：`json`（原生 JSON 对象/数组校验与格式化编辑）、`attachment`（直传 R2 并带缩略图/下载）
  - 关系与计算：`link`（单向/双向对称关联）、`lookup`（基于关联字段自动提取目标表字段值）、`formula`（安全 AST 表达式计算）

### 4.2 多视图与 Web 工作台
- **Grid 网格视图**：高密度数据表格、字段类型图标、显示 `fld_xxx` ID 开关、行内快捷编辑、底部快捷新增行、批量勾选删除、行详情抽屉。
- **Kanban 看板视图**：基于任意单选字段分组展示卡片，支持跨列切换状态实时更新。
- **Gallery 画廊视图**：卡片式视觉排版，自动提取附件首图与核心摘要字段。
- **Form 表单视图**：视图内字段排序与配置、一键开关公开分享 Token、生成 `/f/:shareToken` 独立收集页。
- **实时视图引擎**：支持前端/后端一体化关键词检索、多条件组合筛选（`AND`/`OR` + 11 种操作符）与多字段排序。
- **实时协作**：基于 WebSocket 的在线人数展示与增删改秒级同步。

### 4.3 自动化、开放平台与运维守卫
- **API 密钥体系**：支持签发带细粒度权限 Scope（`base:read`、`records:read`、`records:write`、`schema:write`、`webhooks:manage`）的 `ft_live_...` Bearer Token；数据库仅存 SHA-256 哈希，配合 KV 边缘缓存。
- **OpenAPI 3.1 + Scalar 文档**：`/openapi.json` 自动生成并同步所有接口契约，提供 `/docs` 可交互调试页面。
- **Webhook 事件订阅与审计**：支持订阅 `record.created`、`record.updated`、`record.deleted`、`field.created`、`form.submitted` 事件；支持测试 Ping 触发、投递状态码与耗时日志查询、以及 `HMAC-SHA256` 签名校验。
- **原生 MCP Server**：Worker 内置 `/mcp` 端点，支持 Streamable HTTP (JSON-RPC 2.0) 协议，提供 8 个结构化工具。
- **R2 存储熔断与垃圾回收**：上传前置校验全局配额（默认上限 2 GB，单文件上限 25 MB），每日 Cron（03:00 UTC）自动回收孤儿附件与过期日志。

## 5. 非功能性需求与 SLA 目标

| 维度 | 目标指标 |
| :--- | :--- |
| **API 边缘鉴权延迟** | KV 缓存命中时 < 15 ms |
| **单空间记录读写事务** | 基于 DO 本地 SQLite，常规 100 行查询 < 20 ms |
| **数据一致性** | 单空间内强一致 ACID 事务；跨表双向关联与索引更新同事务提交 |
| **Webhook 投递可靠性** | 基于 Cloudflare Queues，支持 3 次指数退避重试 + 死信队列（DLQ）隔离 |
| **代码可维护性** | TypeScript `strict: true` 零 `any` 逃逸、前后端共享 Zod Schema、关键业务具备完整单元测试 |
